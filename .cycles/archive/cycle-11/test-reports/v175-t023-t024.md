## 4. T-024 会话内练题

### 落点选择（关键决策）
KB 调研后确认：**不是 conversation target**（那是 chat/trajectory 整个视图类型，太重且需接管会话流），而是 **`conversation.input.left`** —— 输入栏左侧的 list slot，官方描述为「模型选择器与发送按钮之间的活动控件」。

### 实现
- `KaogongQuickPractice`：输入栏「📚 练题」按钮 → 点击向上弹出 340px 面板
- 面板：抽题（SRS 优先）→ A-D 作答 → 判分（走 `/api/check`，**自动进错题本**）→ 解析 → 下一题
- 状态完全自管，不订阅会话数据、不改父组件
- 注册用 `ctx.slots.inject('conversation.input.left')` + **try/catch 全包裹**，slot 缺席静默 warn 跳过

### 实测（真机）
| 项 | 结果 |
|---|---|
| 宿主加载 | ✅ 无「注册跳过」警告 |
| 输入栏按钮 | ✅「📚 练题」出现 |
| 面板打开 | ✅ `role=dialog` |
| 抽题 | ✅ 判断推理·图形推理·错题回炉 |
| 作答+判分 | ✅ 4 选项 → 提交 → 显示答案 |
| 选项去重 | ✅ 修复「A A」重复 |
| 与主面板共存 | ✅ 关闭面板后主面板 11 导航正常 |
| 宿主稳定性 | ✅ 无 Failed to load、无 ErrorBoundary |

## 5. 风险闭环记录
T-024 是风险最高的一项（历史 R9 曾因宿主集成导致 GUI 白屏）。本次采取的措施：
1. 选**最轻**的 slot（输入栏 list），不接管会话流
2. 组件完全自管状态，零父组件依赖
3. 注册整体 try/catch，失败只 warn 不抛
4. 沙箱先验证，**确认无降级与无 Failed to load 后才部署主力**
