## 2. 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | `poolApi` 插在 `historyApi` **之后**、`tuxingApi` **之前** | 研究 15 §2.3：`/api/pool/*` 前缀独立无冲突，但语义上「统一池」先于各专项域命中（改朝不加夕） |
| D2 | 摄入走 `poolIngest.ts`（适配层），**不复用 `repoData.parseQuestions`** | 内核/适配分层：适配层知道上游格式，存储层不该知道 |
| D3 | `question.stem` 保留 HTML → 入库时剥标签但**保留 `kgimg://` 占位** | cycle-22 教训⑩：剥 `<[^>]+>` 必须逐字段枚举，img 必须占位保留 |
| D4 | 五维标注缺即空，不用 0/空串冒充 | ㊲ 纪律（可空字段不臆造） |
| D5 | 关系边带 `evidence`（JSON） | 审计友好：任一「同题」判定可追溯证据 |
| D6 | `.kaogong.db` 位于用户数据根（`~/.dsh/kaogong/`），**不入包** | cycle-21 issue#2：市场升级整目录替换包，包内数据必丢 |
| D7 | 库文件原子写（tmp + rename）+ WAL | cycle-18 内容寻址/原子写纪律 |
| D8 | `canonical_id` 优先级 qid > fp > sha256 | 研究 15 §1.1 统一口径 |

## 4. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 库体积增长（27506 题 + 58890 边） | 🟡 中 | FTS 只索引文本列；媒体走引用不复制 |
| 入库吞吐 | 🟢 低 | 实测 0.56ms/题；UPSERT 批量 |
| 双事实源（progress json vs study_event 表） | 🟡 中 | 本轮**只写表、不改读路径**（研究 15 C7：阶段 1 先只写表，阶段 2 再切读） |
| 上游 `.naoku.db` 误写 | 🔴 高 | `SMOKE-KGDB-05` 载体隔离守卫 + 只读连接 |
| 复杂度预算超限 | 🟡 中 | 新文件按域拆分，不进 `manifest.ts`/`http.ts` 大文件 |
