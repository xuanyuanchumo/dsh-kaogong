## v1.34.1 — CI 长期红根治 + 2 个生产缺陷修复

> 补丁版：修复 CI 自 2026-11-21 起持续红（25 文件 / 54 断言），并带回两处**生产代码**修复
> （v1.34.0 已发布、不含此两处）。

### 修复（生产代码）

- **naoku 源可用判定自锁**：统一池摄入需要上游投影库 \.naoku.db\，但该库**只由
  \nsureNaokuDb\ 合并分片产生**，而合并在 **ingest 阶段**才触发——\vailable\ 探针只认
  投影库 → 「从未访问过深度题库端点」的用户/CI 在探测阶段就判定源不可用 → 压根走不到
  ingest → 永远合不出来（池少 27,506 题五维标注 + kadian 边）。
  修法 = 可用判定改为「投影库 **或** 上游分片任一存在」+ 摄入阶段自动合并。
  **实测**：池五维 0 → 27,497，kadian 边恢复。
- **数据根绝对路径判定跨平台错误**：\/api/repos/config\ 的 root 校验原用
  \esolve(raw).startsWith('/')\ 兜底——在 **Linux 上 \esolve('relative/path')\ 返回
  cwd 下的绝对路径且以 \/\ 开头** → 相对路径被误判为合法 → 配置落盘后数据根指向意外位置。
  修法 = 改用 \path.isAbsolute\（跨平台正确）。

### 修复（测试基建 · 不改运行时行为）

- **render harness 硬编码开发机路径**（\../_kgtest/node_modules\）→ CI 上 7 个 render
  旅程文件整体失败。修法 = React 进 **devDependencies**（不进运行时依赖面），harness 改
  「本仓优先 · 开发机回退」。
- **rebuild-safety 测试离线自足**：改自建 fixture 源注入 SOURCE_REGISTRY，走**生产的
  \ebuildPool\ 全路径**（含故障闸 + \olledBack\ 标记）——完全离线自足。
- **npm pack JSON 解析**随 npm 版本变化截断错位 → 定位**顶层数组起点**。
- **占位图 403 判读**：403 是服务端安全模型正确生效（非缺陷）→ 区分 403/404/200 三态。

### CI（从「长期红」到「首次全绿」）

- **CI 装全量题库 + 一次性建池**（\scripts/ci/question-banks.txt\ 清单 + \uild-pool.mjs\），
  **测试代码零改动**（弃用「12 个文件加降级守卫」方案：漏一处 CI 就红且本地覆盖被削弱）。
- **并发克隆 + 稳定 cache key**（key = 题库清单哈希；改 workflow 不让 1.9GB 缓存失效）。
- **CI 实跑全绿**：建池 68.2s（题 87,768 · 关系 583,993 · 出处 230,871 · 五维 27,497 ·
  带图 5,960），**51 文件 / 417 断言全过**（此前 25 文件 / 54 断言红）。
