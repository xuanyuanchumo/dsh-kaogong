## v1.34.0 — 重建不阻塞宿主 + 真增量 + 原子回滚

> 修复用户报告的「重建时 dsh 宿主功能失效、能力崩溃」，并把「全量/增量重建」做成生产级：
> worker 线程执行、整库单事务原子切换、逐源指纹真增量、进度可观测。

### 修复（核心，全部有压测实证）

- **重建冻结宿主 → worker 线程执行**：旧实现把「清库 + 1683 卷 + 27,574 题 + 57 万边」放在宿主进程的
  async 函数里跑，但内部全是**同步** `readFileSync`/`DatabaseSync` —— `await` 只让出微任务、
  让不出已进入的同步调用栈，于是整个 DSH 宿主（所有插件/会话/UI）被独占数分钟。
  改为 worker 线程（`poolRebuildWorker.ts`）+ 主线程只做作业状态机。
  **压测实证**：全量重建 145~155s 期间 1200~1300 次宿主探针**零失败**，主线程事件循环最大阻塞
  **3ms**（旧实现为分钟级）。
- **半成品库 → 整库原子事务**：旧实现先 `DELETE` 并立即 COMMIT，再逐源各自 COMMIT，任一源失败就留下
  **残缺库**（实测故障注入后 question 从 11,649 掉到 11,295，gk-tuxing 354 题被静默删除且 `ok:true`）。
  改为「清空 + 全源 + FTS + 元信息」同一事务，失败整体回滚。
  **守卫 `REBUILD-01` 固化：源异常时 `ok:false` + 旧数据一条不少。**
- **源异常被静默吞掉 → 故障分类闸**：`ingestAll` 区分 `exception`（源实现抛错）与 `unavailable`
  （未安装）。全量模式（已清表）遇 `exception` **整体回滚**；增量模式（未清表）跳过即安全。
  `failures[]` 随响应透出（「哪些源没进来、为什么」可回答）。
- **名为增量、实为全量 → 逐源指纹真增量**：新增 `SourceSpec.fingerprint` + `sourceFingerprints`，
  重建写入逐源指纹、增量按源比对跳过。实测：无变化时 9/11 源跳过（**3.8s**，旧实现每次全量重灌
  ~15s+）；只改一个源时仅重灌该源。
- **重建后缓存/统计不更新 → 跨线程失效重放 + 分片预热**：worker 有独立模块实例，
  `invalidateStatsCache`/`emitDataChanged` 在 worker 里只清 worker 自己的缓存 → 主线程仍显示重建前
  旧统计（实测 `q=0` 假象）。改为主线程在收到 done 后重放失效，并用**分片预热**代替
  「一次性清空后让 N 个请求各算一遍」。
- **重建期读被写锁阻塞 → 只读连接（WAL 快照）**：同一连接参与写锁等待，bm25+JOIN 的重查询实测被拖到
  5,086ms。重建期另开 `readOnly:true` 连接服务读请求，结束时关闭；首次失败自动回落主连接重试
  （不让瞬时错误变成 500）。
- **请求路径上的同步 I/O 全部移除**：
  - 用户态写入（错题 upsert / 进度镜像 / 学习流水 / 检索流水）→ **写队列**（`enqueueUserWrite`：
    入队即返回、`setImmediate` 分片执行、单飞、容量上限）；
  - 生命周期日志 → **内存环形 + 2s 节流刷盘**（旧实现每次请求 `appendFileSync` + 读整文件 +
    可能重写 → 重建期实测把 `/api/status` 卡到 2,316ms，现 8ms）。
- **事件订阅者未按实体过滤 → 过度失效**：`methodology.idxSlot` 任何广播都清空 25 篇方法论索引
  （秒级成本）→ 重建后首次检索现场重建索引。改为声明关心实体（仅 `knowledge` 变化才清）。
- **`/api/status` 缺 `version`**：与 `StatusResponse` 类型声明漂移（沙箱实测发现）。
- **测试 harness 会破坏用户数据根**：`ensurePoolReady` 只要 `ready=false` 就 POST **截断全量重建**
  （`maxFiles:30/maxPapers:30`），而测试与主 profile 共用 `~/.dsh/kaogong` → 实测跑完测试后生产库
  从 86,534 掉到 84,284、`gk-tuxing`=0、`kadian`=0。改为「**库里有题就绝不重建**」
  （ready 是「质量达基线」不是「数据在不在」）。

### 新增

- `adapters/poolRebuildWorker.ts`（worker 入口：进度上报 + 结构化失败收敛 + 动态 import）。
- `poolDb`：`withTxAsync`（异步事务）、**事务嵌套深度感知**（`withTx` 内层不再提交外层 —— 旧实现的
  嵌套 COMMIT 让「整库原子」根本不可能成立）、`clearPoolTables`、`enqueueUserWrite`/`writeQueueDepth`、
  `withReadConnAsync`/`setRebuilding`、`busy_timeout`/`synchronous=NORMAL`。
- `poolSources`：`fingerprintOf`/`sourceFingerprints`/`IngestFailure`/`IngestProgress`。
- `/api/pool/rebuild/status` 透出 `progress{phase,source,index,total}`。
- 检索响应重建期带 `degraded:'busy'` + 可操作提示（诚实降级，非掩盖）。
