# 研究报告：Issue #3 纸质补录「好像没实现」的根因分析与错题本功能完善

**报告时间**：2026-11-14 22:40（北京时间）
**研究者**：ANIC L4 自举循环（cycle-33）
**触发**：用户报告「GitHub Issues#3 好像还没有实现（手动标记纸质刷题记录补录）」

---

## 一、问题定位（三层取证）

### 1.1 功能确实存在，但用户视角不可用

Issue #3 于 v1.16.0 交付：`/api/history/search` 搜索候选 → `/api/history/entries` 三态补录 → 错题自动入 SRS → 批次撤销。UI 入口在**深度题库页**（`KgHistoryImport` 四步旅程卡片）。守卫 SMOKE-HIST-01..08 与 C22-02 全绿——**测试全部通过，但用户实测「搜不到」**。

### 1.2 根因一（P0）：补录搜索的两条通道在真实环境双双失效

| 通道 | 设计 | 真实环境表现 |
|---|---|---|
| ① 深度题库 DB 搜索 | `searchQuestionsByStem`（27506 题五维标注，LIKE 全量） | **`data/.naoku.db` 不存在**——该 DB 由 GongkaoNaoku 仓库的 Python 合并脚本生成，用户未装该仓库或未跑合并 → 通道恒空 |
| ② 目录题库兜底 | `getRandomQuestions(module, 12)` **随机抽 12 题** → 按关键词过滤 | **兜底形同虚设**——511 个文件的模块随机抽 12 题，关键词过滤后命中率≈0（实测：随机抽题与用户纸质题吻合概率趋近于零） |

**结论**：装了真题库（gwy-zhenti，1683 套）但没装深度题库的用户，`/api/history/search` 永远返回空列表 → 四步旅程第一步「搜候选」就卡死 → 用户感知「功能没实现」。**此前 v1.26.0 关闭 issue 的说明对本场景不成立**（当时只验证了 harness 测试环境：mock DB 就绪）。

### 1.3 根因二（P1）：补录入口埋在深度题库页深处

补录组件仅 1 处使用（深度题库页滚动区中部），错题本页面（用户收到「错题已进错题本」提示后最可能回去的地方）**无任何补录入口**，且错题本视图本身功能贫乏（45 行：仅两张统计卡 + 条目列表，无筛选/无回炉入口/无补录）。

### 1.4 根因三（P2）：关闭说明与真实可用性脱节

Issue 关闭时引用的证据全部是 harness 测试（mock 环境下 DB 就绪），没有覆盖「只装真题库」这一真实用户主流配置——教训⑱（环境性缺陷用干净环境复现）在 issue 验证环节未执行。

---

## 二、修复方案（cycle-33 实施）

### 2.1 P0：补录搜索第三通道——真题卷全文扫描（新增）

- 复用 `buildPaperIndex`（磁盘快照，13ms）+ `loadPaper` 逐卷解析（实测 ~18ms/卷）
- **限量早停**：行测卷按年份倒序扫描，找满 `limit` 即停；`maxPapers` 上限（默认 80 卷 ≈ 1.4s 最坏情况）
- 结果带溯源元数据：`paperId`/`exam`/`year`/`no`/`paperFile`（用户可点回原卷核对）
- 与既有通道去重（`contentSig` 同源）；`matchSource: 'papers'` 标注

### 2.2 P1：错题本页面功能完善（新增）

- **筛选条**：模块筛选（六模块 chips）+ 状态筛选（待消灭/已掌握/全部）
- **回炉入口**：「🔁 SRS 回炉」按钮 → 跳深度题库页 SRS 抽题（复用 `onGoWrongbook` 的反向导航）
- **补录入口**：内嵌「📥 纸质补录」折叠卡片（复用 `KgHistoryImport`，props 透传）
- **条目增强**：展开/收起题干全文 + 来源标签保留 + mastered 灰化保留

### 2.3 P2：验证纪律补丁

- 守卫 C33-01..04（真题卷扫描通道 / 错题本筛选 / 双入口 / 溯源元数据）
- smoke 运行时断言：真题卷搜索通道在「无 DB」环境返回非空（教训⑱的干净环境验证）

---

## 三、结论

Issue #3 的功能**代码存在但真实环境不可用**（P0 搜索通道失效是主因），本次修复让「只装真题库」的主流用户完整走通四步旅程；错题本页面从「纯展示」升级为「筛选 + 回炉 + 补录」的工作台。修复后 issue #3 的关闭理由才真正成立。
