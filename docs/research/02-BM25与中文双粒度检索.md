# 02 · BM25 与中文 bigram 双粒度：从「词频饱和」到「方法论语料检索」

> dsh-kaogong 研究文档 · cycle-19

## 1. 数学定义

BM25 是概率检索模型的经验_extension，对查询 q 在文档 D 上的打分：

```
score(q, D) = Σ_{t∈q} IDF(t) · (f(t,D)·(k1+1)) / (f(t,D) + k1·(1 - b + b·|D|/avgdl))
```

- `k1=1.2` 控制词频饱和：一个词出现 5 次之后，第 6 次的边际增益趋近 0
- `b=0.75` 控制文档长度归一：长文档不是天然更相关
- `IDF(t) = ln(1 + (N - df + 0.5)/(df + 0.5))`：越稀有的词信息量越大

**噪声治理（cycle-18 教训㉜）**：中文 bigram 下任何中文串都会产生命中，实测噪声分数反而高于真实短查询。正解=**只裁尾**（`score < max(1.0, top×0.15)` 且永留首条）+ 三档 confidence/phraseHit 提示，**低置信度结果不丢弃**。教训：给「相关性」建模前先实测分数分布，别用直觉阈值。

## 3. 中文思维：语言/学习场景启发

- **方法论检索 = 「按语义相关度查语法书」**：用户问「数量关系怎么做」，bigram 把「数量」「量关」「关系」三个词元同时命中索引，标题加权让《数量关系章》排在《判断推理总述》前面——这就是「按图索骥」的量化。
- **双粒度的语言学依据**：中文没有空格分词，单字粒度兜底召回（「申」命中「申论」），bigram 粒度保证精度（「申论」是独立语义单元）。**召回与精度的矛盾用多粒度并集化解**，而不是单粒度内做权衡。

## 4. 工程实践价值

1. **整数权重 postings**：权重是整数，JSON 序列化紧凑（336KB 语料 → 索引 <500KB），查询时与查询词权重相乘完成打分——**用整数运算回避浮点误差与序列化体积**。
2. **fixtureHash 快照失效**：语料文件的 hash 进快照键，上游语料更新后索引自动失效重建，无需手工清缓存——「内容寻址」思想（同 git blob hash）。
3. **只裁尾不过滤**：检索结果的「展示置信度」与「数据完整性」分离——模型/UI 自己决定如何呈现低置信度结果，引擎不替下游做截断决策。
