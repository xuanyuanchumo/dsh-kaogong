# 25-统一架构的数学模型与数据结构.md

> cycle-60 收敛总纲：把分散的「层」写成**同一个代数结构的不同投影**，避免各自为政的口径漂移。
> 纪律：每个模型必须能在仓库指出代码落点（文件:行号）与可运行验证；不写无法落地的空谈。

---

## 0. 一句话

> 整个系统是一个**以 canonical 身份为键、以关系图为骨架、以租户命名空间为分区、以新鲜度为闸门**的确定性函数：
>
> `answer(state, query) = Read ∘ Cache ∘ Route ∘ Gate ( Store(canonical_id, ws) , query )`

任何新功能若不能放进这条链，先问「它属于哪个投影」，而不是新造一条旁路。

## 1. 五个核心数据结构（数学定义 → 代码落点）

### 1.1 身份层：规范键 `C`

```
derive(qid, fp, stem) = q:<qid>  若 qid 存在
                      ∣ fp:<fp>  若 fp 存在（上游 SHA-1 40hex）
                      ∣ h:<sha256(stem)[0:16]>  兜底
```
- **性质**：确定性、跨源稳定、幂等（同一题两次摄入得同一键）。
- 图推特例：指纹须含 img 内容寻址文件名，否则通用题干会把不同考点题误并（cycle-57 事故）。
- 落点：`src/adapters/poolDb.ts:deriveCanonicalId` / `contentFingerprint`
- 验证：`tests/smoke/kgdb.test.mjs` KGDB-12/13（1895 图推零丢失）。

### 1.2 关系层：统一边表 `E`

```
E ⊆ (rel_type, src_kind, src_id, dst_kind, dst_id, weight, evidence)
```
- 12 种 rel_type 共存一张表 → **新增关系类型零 DDL 迁移**（只需词表登记）。
- PageRank / 邻域 / 最短路 / 影响面全部在同一张图上计算，不另建索引图。
- 落点：`src/adapters/poolDb.ts:REL_TYPES` / `relation` 表；`src/server/manifest.ts` 图算法族
- 验证：`tests/smoke/kgdb-runtime.test.mjs` KGDB-03b。

### 1.3 分区层：租户键 `W`

```
wsKey(raw) = slug(raw)[-40:] + '-' + sha1(raw)[0:8]
```
- **性质**：可读 + 防碰撞；任何含用户态数据的缓存/表第一维度必须是 W。
- 落点：`src/server/ws.ts:wsKey`；`wrong_book(ws,sig)` / `user_kv(ws,domain,k)` / `graphCache` 键
- 验证：`tests/unit/cache.test.mjs` CACHE-02（跨 ws 不污染）、C60-FRESH 系列。

### 1.4 新鲜度门 `F`：换源的布尔谓词

```
F(db) = [schema ≥ 6] ∧ [cf 污染行 = 0] ∧ [图推题数 ≥ 1895×0.99]
```
- 这是从「旧库直读」过渡到「统一库直读」的**单调闸门**：rebuild 后一次性翻转为 true，且不会回退（除非数据再损坏）。
- 换源的三个读层（naoku / history / papers）**共用同一个 F**（`computeFreshness`），杜绝「面板说 fresh、端点说 stale」。
- 落点：`src/server/poolObservability.ts:computeFreshness`
- 验证：`tests/smoke/pool-freshness.test.mjs` C60-FRESH-01/03/04。

### 1.5 缓存键：四维积 `K`

```
K = domain × wsKey × rootFp × stableParams(params)
```
- 缺任一租户级维度 = 跨项目污染（cycle-17 R20 事故）。
- LRU 按域隔离，TTL 由域声明（graph 5s/24 槽，静态语料长 TTL）。
- 落点：`src/server/cache.ts:buildCacheKey/createCache`
- 验证：`tests/unit/cache.test.mjs` CACHE-01..06。

## 2. 三个统一算法（同一语义只有一个事实源）

| 语义 | 唯一事实源 | 消费方 | 防漂移守卫 |
|---|---|---|---|
| PageRank（d=0.85, iter=40） | `src/shared/kernel.ts:pageRank` | 服务端 manifest + 客户端 graph-analytics（真 import，combo 23 模块） | KERNEL-07 + KERNEL-SHARE |
| 弱点权重 `1/(rate+0.15)` | `src/shared/kernel.ts:weaknessWeight` | SRS / 排程 / 池抽题（业务先验差异留在调用侧） | KERNEL-09 |
| 环形缓冲裁剪 | `src/shared/kernel.ts:ringPush/ringTrim` | telemetry / methodologyApi | KERNEL-11 |

**纪律**：业务先验（无数据时 rate=0.5 还是 0）是**语义差异**，不塞进内核；公式本身才是共享对象。

## 3. 分层与依赖方向（低耦合高内聚）

```
L4 内核 kernel.ts ──────── 纯确定性算法（零 IO）
      ↓ 值导入（bundler 白名单 shared/kernel）
L3 存储 .kaogong.db ────── 唯一事实源（question/relation/paper/…）
      ↓ 域工厂注入（buildDomains）
L2 适配 poolSources 注册表 ─ 外源只读 → 入库；换源由 F 门控
      ↓
L1 外源（16 仓库）──────── 永不直读于请求路径（fresh 后）
```
- 单一事实源端点：manifest（能力声明）/ kernel（算法）/ poolDb schema（数据形态）/ computeFreshness（换源判定）。
- 检索统一信封 `{query,results,total,took?,confidence?}` + 外壳 `{id,source,title,snippet,score?,meta?}` 由 `SearchProvider` 注册表派生，源特有字段进 meta，**不混用跨源不可比打分**。

## 4. 场景启发

- **「我的进度怎么变成别人的」**→ 缓存键漏了 W（§1.3）。加维度比加断言更根本。
- **「图推题怎么少了一千道」**→ 身份指纹漏了图片维度（§1.1）。归一前先枚举区分因子。
- **「换源后数据没了」**→ 门 F 未过就切源（§1.4）。单调闸门让切换成为数据状态的函数，而非代码分支的赌注。
- **「同一张图两侧中心性不同」**→ 算法有两份实现（§2）。改成真 import 而非镜像常量。
