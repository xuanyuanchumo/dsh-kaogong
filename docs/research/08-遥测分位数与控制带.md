# 08 · 遥测环形、p50/p95 与 Western Electric 控制带：从「过程控制」到「白盒可观测」

> dsh-kaogong 研究文档 · cycle-19

## 1. 数学定义

**分位数**：p50（中位数）= 50% 请求快于此值；p95 = 95% 请求快于此值。**服务延迟监控看 p95 而非均值**——延迟分布右偏长尾，均值被少数极端值拉高/拉低，p95 对「用户实际体验变差」敏感且稳健（统计学术语：resistant statistic）。

**Western Electric 规则（WE Rules）**：休哈特控制图（SPC, Statistical Process Control）的判异规则族，检测「过程是否失稳」：
1. 单点超出 3σ 控制限
2. 连续 3 点中 2 点在同侧 2σ 区外
3. 连续 5 点中 4 点在同侧 1σ 区外
4. 连续 8 点全在同侧

任一触发 = **系统性漂移**（非随机噪声）→ 需要查明原因，而非继续盲目优化。

**控制带（Control Band）**：把复杂度预算（config `complexity_budget: 180`）当作控制上限，周期采样各文件复杂度 → 快照入 `band-history.json` → WE 规则判漂移。连续 2 轮超预算 = CB5 熔断条件（自主带 alarm）。

## 2. 本插件代码落地

| 落点 | 内容 |
|---|---|
| `src/server/http.ts` | 遥测域：`recordRequest` 环形采样（内存 O(1)），端点级 p50/p95 计算；`__unmatched__` 聚合桶（cycle-18 ㉗ 影子端点治理：未声明路径不进对账表，另开观测余量） |
| `/api/telemetry` → 白盒面板 | 「能力对账×性能表」：manifest 声明 ↔ 运行态端点 ↔ p50/p95 三方对账，慢端点 p95 降序 |
| ANIC 技能 `band-detector.mjs` | WE 规则机器实现：默认报告模式（告警是数据），`--strict` 才是 CI 硬门——**「告警不等于失败」的语义分层** |
| `.cycles/config.yml` | `complexity_budget: 180`——单 combo 文件 10+ 视图的工程实际预算 |

**假阳性教训（v1.8）**：遥测记 `mountPath+rel` 而 manifest 声明 `/api/graph` → 对账 100% 失配全标「未声明」。教训：**凡「声明 vs 运行态」对账，两侧口径必须由同一常量派生**（cycle-18 ㉗ 后由 `isDeclaredEndpoint()` 单点派生）。

**度量口径教训（cycle-18 ㉖）**：覆盖矩阵按「该维度对此对象是否成立」先裁剪分母——常识判断不考公式，公式维度不进其分母。**统计口径错了，统计越精确越误导**。

## 3. 中文思维：语言/学习场景启发

- **不以均值论英雄**：一个班级平均分 80 可以是「全班都 80」也可以是「一半 100 一半 60」——p50/p95 分位数把「分布形状」带进判断。学习方法同理：错题率的中位数比平均分更能代表真实水平。
- **月晕而风，础润而雨**：WE 规则的本质是「在暴雨（事故）之前读出风月（前兆）」——连续偏移比单点异常更可信。学习质量同理：**一次考砸可能是偶然，连续三次偏移一定是方法问题**。
- **控制带=度量的度规**：复杂度预算 180 不是道德标准而是「统计控制限」——单文件偶尔 181 是噪声，连续两轮 200+ 是漂移，需要拆分而非辩解。

## 4. 工程实践价值

1. **环形采样 + 在线分位数**：遥测不做「记录一切」，环形缓冲保证内存上界；p50/p95 在采样数组上即时计算——观测不拖累被观测系统（Heisenberg 纪律）。
2. **报告模式 vs 门禁模式**：band-detector 默认只报告（数据），`--strict` 才拦截——同一份计算服务两种消费者（人看/CI 拦），语义不混用。
3. **影子桶保留观测余量**：未声明端点不进对账表（防假阳性）但进 `__unmatched__`（不丢信息）——**过滤污染源而非销毁证据**。
