# 10 · 流动语义与桑基思维：从「边上的粒子」到「能力流可视化」

> dsh-kaogong 研究文档 · cycle-19

## 1. 定义与原理

**桑基图（Sankey Diagram）**：能量/流量守恒的可视化——节点宽度=流量大小，边宽度=分支流量，**流入=流出**（不守恒的节点是账目错误）。它的数学内核是流网络（Flow Network）：容量约束下的守恒律。

**边粒子动画**：在边上匀速移动的小点，方向=数据流向。本质是把「静态拓扑」升级为「有向流」——同一张图，加粒子后读者能分辨「谁生产、谁消费」。

**语义边分类**：不是所有边都代表流。本插件按四类语义登记粒子集合：

```
KG_FLOW_RELS = ['produces', 'consumes', 'feeds', 'serves']
```

- `produces`：数据域 → 数据生产（适配器产出索引/题库）
- `consumes`：UI → 消费端点数据
- `feeds`：server → 喂数据给视图/工具
- `serves`：http → 对外服务

只有这四类边画粒子——**「流」是语义声明而非视觉装饰**。

## 2. 本插件代码落地

| 落点 | 内容 |
|---|---|
| `src/client/graph-physics.ts:18,337-344` | `KG_FLOW_RELS` 四类流动语义边沿线画匀速粒子；每边相位由端点 id 散列（确定性：不用 Math.random，同输入同画面） |
| `src/client/graph-analytics.ts` | `GRAPH_NODE_META`/`GRAPH_EDGE_META` 图语义色板与层级单一事实源——新增节点/边类型必须在此登记，否则 UI 落灰色 fallback |
| `src/client/obs-view.ts` | 白盒「能力流」卡（W2c）：量化条呈现 生产→消费 链路健康 |
| `src/server/http.ts` | 图谱域输出 nodes/edges 带 rel 语义标签；遥测 recordRequest 提供真实流量计数 |

**相位散列的细节**：`phase = hash(from+to) % period`——相邻边粒子错峰，避免「全体粒子齐步走」的机械感，同时完全确定可复现。

## 3. 中文思维：语言/学习场景启发

- **问渠那得清如许，为有源头活水来**：桑基图的核心问题是「活水从哪来、流到哪去」。能力流对账卡的灵魂问题相同：**每个端点的数据从哪生产、被谁消费**——孤儿端点（无人消费）与幽灵消费（无生产）在守恒律下现形。
- **源清则流清，源浊则流浊**：数据质量沿流传播——适配器解析错 → 端点数据错 → UI 显示错 → 用户误判。粒子方向让「流」的因果链可见，调试时沿粒子反向找源头。
- **井然有序 vs 川流不息**：静态布局（04 篇）解决「井然有序」（结构清晰），流动粒子解决「川流不息」（活性可见）——**一张好图需要秩序与活性的双重表达**。

## 4. 工程实践价值

1. **守恒律作为审计工具**：能力对账（manifest 声明 ↔ server 实现 ↔ UI 消费）数学上就是流网络守恒检查——声明未实现=源头缺失；实现未消费=流出缺失。cycle-19 R-OBS-2 把三列对账做成白盒卡，孤儿/幽灵节点红色标记。
2. **粒子是廉价的高信息密度动画**：零依赖（Canvas 2D fillRect）、确定性（id 散列相位）、可暂停（离线预收敛后仅按需重绘）——动效的信息价值/性能成本比极高。
3. **语义边集是扩展点**：新增数据链路时在 `KG_FLOW_RELS` 登记即可获得粒子表达，动画代码零改动——**开闭原则在视觉层的应用**。
