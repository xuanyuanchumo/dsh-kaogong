# 21 · 跨源去重治理：内容指纹合并 + 来源全标记 + 解析多版本

> 前置：[16-题库覆盖审计.md](./16-题库覆盖审计.md)（qid 命名空间隔离的设计取舍）· [19](./19-阶段2取题层升级.md)

## 1. 问题（用户指出的真实缺口）

qid 命名空间隔离（研究 16 §2.2）防了「跨源撞库误合并」，但带来新问题：
**xingce-app 与 gwy-zhenti 的同内容题**（qid 不同源）各存一行——实测
**内容重复 12177 组 / 可合并冗余 41755 行**（排除合成 stem 后 9906 组 / 33933 行）。
「入库没去重吗？」——是真实缺口。

## 2. 三原则（用户硬要求 → 机器化）

| # | 原则 | 落地 |
|---|---|---|
| ① | 题目/选项相同的重复行合并为一条 | `contentFingerprint`（sha1(norm(stem)+'|'+norm(options)) 24 hex）+ `question.content_fp` 列 + UPSERT 前查重归并 |
| ② | 来源必须全部标记 | 合并不删行内出处——归并行挂 `question_source`（每源一行）；出处行 230743 **全保留** |
| ③ | 解析不同必须保留且带来源 | 新表 `question_analysis`（canonical_id+source_id+local_key 唯一，多版本全量留痕）——111979 行 |

## 3. 指纹设计的关键决策

### 3.1 归一化
剥 HTML 标签 / kgimg 占位 / 全部空白 / 小写——**内容等价性判断**，不是格式判断。

### 3.2 长度判据放「组合后」（cycle-40b 修正）
首版只判 stem ≥40——资料分析「材料+公式图+短问」剥图后 stem 只剩 9 字（实测），
指纹全空 → 212 组漏合并。修正：`norm(stem)+'|'+norm(options)` **组合后** <40 才放弃
（纯退化行：选项全图、stem 纯占位——指纹无区分力，不合并是安全选择）。

### 3.3 明确不合并的（设计内保留）
- gk-tuxing 合成 stem（`【图形推理 · cat】`）同文不同图——合并会吞掉不同图 → 指纹跳过
- 残留 21 组 xingce-app 内部重复：选项全公式图（归一后 30 字）→ 无指纹 → 保留（安全侧）

## 4b. 实施期踩坑（R45/R46——列序错位与 UPSERT 吸并）

- **R45 · 列序错位**：naoku/xingcezhenti 源里各自的**私有 33 列 insQ**（旧 schema）
  与共享 `QUESTION_COLS`（34 列含 content_fp）不一致——run 传 34 参打在 33 列占位符上，
  `column index out of range` 被 catch 吞 → naoku 行 **0**（但 relations 191377 全量，
  因为 putRelation 在 catch 之外的循环体里照跑）。**症状组合**（行 0 + 关系全量 + 出处
  全量）是「INSERT 失败被吞」的指纹。正解 = 所有源统一走 `prepareQuestionUpsert`
  （SSOT 列清单），私有 INSERT 全部删除。
- **R46 · UPSERT 吸并**：归并分支最初仍调 `insQ.run(canonical=mergeTarget)`——
  canonical_id UNIQUE 冲突走 DO UPDATE，把本源行「吸进」主行（source_id 保持主行值）。
  正解 = 归并分支**绝不 INSERT**：只挂出处（putQuestionSource）+ 解析版本（putAnalysis）
  + 富字段回填（只填空位的定向 UPDATE）。
- **附**：`smoke` 与宿主共享用户数据根——池被调试清空后 smoke 全挂。加**启动自检重建**
  （空池自动小样本重建，20s 级）；IMG-04 的带图优选加**富行定向补捞**（rich 题不足
  n/2 时定向捞带图/带五维行灌入头部——候选池 n*3 行在 15% 带图占比下会随机漏空）。

## 5. 数据流（三源合并示例）

```
naoku 先入库（qid=5509487, cf=c6904455…）→ 主行
xingce-app 后到（qid=56252, cf=c6904455…命中）→ 归并：
  · 不插 question 行
  · question_source + 一行（source=xingce-app）→ 来源标记
  · question_analysis + 一行（source=xingce-app，解析版本）
gwy-zhenti 再到（同 cf）→ 同上归并
```

**查询**：`/api/pool/question?id=…` 的 `sources[]` 列出全部来源；`analysisVersions`
（后续可加）列出多版本解析。

## 6. 中文思维

- **「合并户口，不烧档案」**：去重是把户口并到一起，每个人的档案（出处/解析）原封不动
  跟着走——查「这道题我见过没有」只有一个人，查「这道题谁收过、怎么讲的」一查一个准。
- **「认不出的字不硬认」**：选项全是公式图的题，指纹没有区分力——强行合并可能吞掉
  不同的图。**留 21 组不合并**不是没做完，是「不确定就不动手」的安全侧。
