### 2.3 域链分发真实顺序（`http.ts` handleApi）

```ts
async function handleApi(path, params, post, method, wsRaw, port) {
  if (path.startsWith('/api/repos')) {                    // ① 异步域前置于同步链
    const r = await repoManager.handle(...)
    if (r !== undefined) return r
  }
  return domains.methodologyApi.handle(...)               // ② 同步域链
    ?? domains.srsApi(...)
    ?? domains.historyApi.handle(...)
    ?? domains.tuxingApi.handle(...)
    ?? domains.naokuApi.handle(...)
    ?? domains.paperApi.handle(...)
    ?? domains.dataApi(...)
    ?? coreApi(...)                                       // ③ 兜底
}
```

**含义**：

- `repoManager` 独占 `/api/repos*` 前置（git 作业是异步的）；
- 其余 7 个域以 `??` 短路链分发——**先命中先返回**，故域顺序即优先级；
- `coreApi` 兜底 `/api/status` 等核心端点；
- **`poolApi` 的插入位置**：建议置于 `historyApi` 之后、`tuxingApi` 之前——`/api/pool/*` 前缀独立，无冲突风险，但排在前面可让「统一池」在语义上先于各专项域被命中。

## 5. 中文思维：全局整合的启发

- **「先立总谱，再补细节」**：四份研究若各自孤立推进，会长出四套互不相认的目录与命名。总谱先行（阶段 0-4 + 统一口径），细节才不会打架。
- **「改朝不加夕」**：域链顺序即优先级——新增 `poolApi` 的位置不是随手排的，它决定「统一池」与各专项域谁先命中，是**架构立场**的体现。
- **「未声明者不可取」**：DSH 的 `ctx.inject` 语义（未声明的服务取不到）与本项目的「manifest 未登记即对账漂移」是**同一条纪律的两面**——**声明是取用的前提**，不是文书。
- **「器要齐备，信才敢立」**：研究 13 造器（存储层），研究 12/14 立信（算法与边界）。器未成时先立信，会写成空中楼阁；所以主线必须是**先阶段 1（器）后阶段 2/3（信）**。
- **「双写是迁移期的原罪」**：存储层落地必然经历「旧 json + 新表」双写期，**必须明确谁写谁读**，否则同一份学习记录会有两个事实源——这正是本项目历史上「单一事实源」纪律要防的事。

## 6. 工程实践价值

1. **消除三处口径冲突**（canonical_id / 库名 / 阶段编号）——避免四份研究并行实施时互相推翻。
2. **发现一个实施前提缺口**（C5：llm 未声明）——不修则研究 11 的模型方案在第一行代码就会失败。
3. **量化了真实改动面**（17275 行 / 67 端点 / 6 工具 / 23 视图 / 14 域 / 8 adapter）——实施计划不再建立在目录清单的想象上。
4. **暴露两跳现状与三跳目标的差距**（C6）——明确「适配层输出从直接返回改为写库」这一**唯一的关键改造点**。
5. **阶段 0 的守卫先行**（内核边界机器化）——在写任何新代码前，先把「什么算违规」变成可执行的断言，防止新功能绕过边界。
6. **四份研究各自仍可独立查阅**，但**实施必须按本篇的统一主线走**。
